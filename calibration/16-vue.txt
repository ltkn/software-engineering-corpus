Goal: Ship a composable that owns its watchers and cleans up after itself in any host component.
Wiring:
export function useOrderStream(id: MaybeRefOrGetter<string>) {
    const scope = effectScope()
    const events = ref<OrderEvent[]>([])
    scope.run(() => {
        watch(() => toValue(id), (v, old) => { if (old && v !== old) events.value = [] }, { immediate: true })
        watchEffect(onCleanup => { const c = subscribe(toValue(id), e => events.value.push(e)); onCleanup(() => c.close()) })
    })
    onScopeDispose(() => scope.stop())
    return { events: readonly(events) }
}
Why: an effect created outside a scope belongs to whichever component happened to call the composable, so an early `return` in that component or a call from a non-component context leaks a subscription. The scope makes ownership explicit, `onCleanup` handles per-run teardown, and `onScopeDispose` ties the scope's lifetime to the host's; the caller cannot forget to stop it because there is nothing to stop.
Pitfall: returning a raw `ref` and letting consumers write to it; calling the composable in `setup` conditionally, so the scope sometimes exists and sometimes does not; putting the unsubscribe in `onUnmounted` inside the composable, which fires too late for a watcher that re-runs.
Verification: a unit test mounts, unmounts and asserts the subscription closed exactly once, and a second test flips the id twice asserting old connections close before the new one opens.

  if (err.name === 'NotAllowedError' || err.name === 'AbortError') return 'Passkey sign-in was cancelled or timed out.';

});
Why: the three network-plus-hardware steps share one mutation, so there is one spinner, one error, and no half-state where options arrived but the button re-enables. Authenticator rejections are named locally because the backend never sees them, while every backend refusal keeps its worded detail.
Pitfall: three separate mutations where the user clicks through a stale options response; or surfacing the raw NotAllowedError name to the user; or enabling the button mid-ceremony so a double click starts two overlapping get calls.
Verification: a test with mocked startAuthentication rejecting NotAllowedError asserting the friendly sentence and no fetch to authenticate, plus a busy test asserting the button stays disabled across all three awaits.
