Design decision: POST creates, PUT replaces, PATCH modifies, DELETE removes; GET never mutates.
Contract fragment:
POST /users -> 201 with Location: /users/{id}
DELETE /users/{id} -> 204, no body
Why: method semantics let intermediaries, clients, and audits reason uniformly; a GET that mutates breaks caching, prefetching, and CSRF assumptions at once.
Versioning note: method set frozen per major version; new actions become sub-resources, never verbs in URLs.
Verification: contract test asserts no state change on any GET; method-not-allowed returns 405 with an Allow header.

Why: clients branch on codes, not message strings; precise codes make retries, auth flows, and error handling programmable.
