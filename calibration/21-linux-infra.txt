Goal: Make a failed deploy reversible in one command, with the rollback rehearsed instead of improvised.
Wiring:
image: registry.internal/orders-api:2026.10.07-142-a3f9c1d   # immutable tag, never :latest
helm upgrade --atomic --timeout 5m orders-api ./chart --wait
kubectl apply --server-side --field-manager=pipeline -f deploy/
kubectl rollout history deploy/orders-api; kubectl rollout undo deploy/orders-api --to-revision=7
serviceAccountName: orders-api; automountServiceAccountToken: false
Why: a rollback only means something if the previous revision still refers to the previous image, which `:latest` plus `IfNotPresent` or `Always` destroys; `--atomic` rolls back on a failed upgrade so a half-applied release does not sit in production; server-side apply removes the client-side merge conflicts that surface during the incident. The service account token is mounted only when something reads the API, because an unneeded token is an credential in a pod that can be read.
`helm upgrade --atomic --timeout 5m orders-api ./chart --wait` ends `STATUS: deployed  REVISION: 43` on the good path and `STATUS: failed  … deployment "orders-api" exceeded its progress deadline` followed by `Rollback was successful` on the bad one — those two lines are the entire value of `--atomic`.
`kubectl rollout history deploy/orders-api` then prints `REVISION  CHANGE-CAUSE` with `43  2026.10.07-142-a3f9c1d`, and the CHANGE-CAUSE being an immutable tag is the only reason `--to-revision=42` means what the on-call thinks it means.
Misconfiguration: secrets referenced without declaring whether they are optional, so a missing one appears as a crash loop on first traffic; rollback performed by re-running the pipeline, which re-resolves `:latest` and redeploys the broken build with a green check; no recorded revision, so "the last good one" is a guess.
Verification: a drill deploys a deliberately broken image and the automatic rollback fires with an alert; a second drill rehearses a manual undo to a named revision under a time budget; the deploy record names the revision, the tag and the diff.
