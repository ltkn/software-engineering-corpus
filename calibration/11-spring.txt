Verification: `ApplicationModules.of(...).verify()` runs in the build and fails on a deliberate cross-boundary import; the published-event test asserts an event is stored exactly once per state change and that the relay has not been bypassed (rationale in 19, relay mechanics in 13).

Goal: Assert an HTTP contract from the test side without assembling a template by hand.
Wiring:
@Test
void returnsProblemDetailOnCrossTenantRead(RestTestClient client) {
    client.get().uri("/orders/{id}", otherTenantOrderId).exchange()
          .expectStatus().isForbidden()
          .expectBody().jsonPath("$.title").isEqualTo("Forbidden")
          .jsonPath("$.type").exists();
}
Why: the `RestTestClient` style is the direction for Boot 4 tests — real serialization, real status mapping, no `MockMvc` string plumbing for assertions that should read like the contract. It catches the class of defect a mocked call cannot: the mapping from exception to problem details, and the header the client actually depends on.
Misconfiguration: a mock-heavy slice that asserts internal calls rather than the response, so the test survives a change to the wire format; or a full-context test per assertion, so the suite is slow and gets skipped.
Verification: the slice runs without the database by stubbing the repository, asserts status, content type and the problem-details shape, and the security slice covers the same route for anonymous, owner, same-tenant stranger and foreign principal.
