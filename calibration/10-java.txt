Check: entity-vs-record decision recorded per class; builder usage justified by optional/defaulted parameters.

Concept: JPMS migration pitfalls — split packages and automatic modules bite at deploy, not in the IDE. Migration pattern.
Modern form: one package in exactly one module; third-party jars without module-info consumed as explicit requires after jdeps analysis, with add-modules/selective opens declared in the launch config, not scattered flags.
Why: split packages (same package in two jars) fail modular runs while classpath runs stay green; automatic modules read everything and export everything, silently widening access the modular build later revokes.
Counter-pattern: unnamed-module development "temporarily" for two years, then a flag-day migration under release pressure.
Check: modular build from day one in CI (even while shipping classpath); jdeps split-package scan fails the build.

Concept: JDK 25's small-but-binding additions, with status labels (JEP numbers verified against the 2026-10 ledger). Record-constructor and flexible-constructor work rides JEP 513; compact object headers JEP 519 is a product option with a per-workload footprint effect; generational Shenandoah finalizes in 25 (JEP 521) alongside G1/ZGC for selection heuristics; JFR gains CPU-time profiling (JEP 509, experimental, Linux-only), cooperative sampling (JEP 518), and method timing/tracing (JEP 520); JEP 510 adds the KDF API; PEM encodings remain preview (JEP 470).

Concept: The preview neighbor chain through JDK 27, so a "latest idiom" never claims finality before it has it.
