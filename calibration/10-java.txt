    }
    private void matchSameDay(Map<LocalDate, List<TradePair>> byDay, TradePair d) {
        List<TradePair> same = byDay.getOrDefault(d.day(), List.of());
        for (TradePair a : same) executor.apply(a, d, Math.min(a.qtyMinor(), d.qtyMinor()));
    }
    private void matchBedAndBreakfast(List<TradePair> ordered, TradePair d) {
        for (TradePair a : ordered) {
            if (!a.day().isAfter(d.day()) || a.day().isAfter(d.day().plusDays(30))) continue;
            executor.apply(a, d, Math.min(a.qtyMinor(), d.qtyMinor()));
        }
    }
    private void matchPool(List<TradePair> ordered, TradePair d) {
        for (TradePair a : ordered) executor.apply(a, d, Math.min(a.qtyMinor(), d.qtyMinor()));
    }
}
Why: grouping is O(n), the sort is O(n log n), each sweep is O(n) in the acquisitions, so the whole match is O(n log n) time and O(n) memory — the sort dominates and nothing is quadratic. The first hypothesis was a single pass with no sort; it was killed by a fixture where two same-day lots matched in arrival order instead of price order and the gain differed by 3 cents. The executor interface keeps the ordering rules testable without I/O, and the LinkedHashMap preserves day-insertion order so the sweep is deterministic for equal keys. A sanity check before trusting: the sum of matched quantities plus the pool remainder equals the input quantities exactly.
Counter-pattern: nested loops per disposal rescanning all acquisitions with a contains check inside (O(n squared) per disposal, minutes at 10k trades); or recomputing the day groups inside the disposal loop instead of once.
