Concept: Threat modeling starts from trust boundaries, not from a checklist. For this stack the boundaries are browser to SPA, SPA to API, API to database, service to Kafka, and CI to production.
Vulnerable pattern: A team enumerates STRIDE per component instead of per boundary, producing fifty theoretical threats on the logging library and none on the tenant-propagation path.
Why it fails: Components are where code lives but boundaries are where attackers cross; per-component analysis diffuses effort evenly instead of concentrating it where trust changes.
Remediation: Model each boundary with its assets, allowed flows, and one abuse case; the gateway-to-service tenant handoff gets modeled before any library.
Regression control: Threat model reviewed on every boundary change (new webhook, new consumer); review recorded as a checklist item in the PR template.

Concept: STRIDE-per-boundary applied to the API-to-database boundary.

Concept: Security invariants are properties that must hold in every state, stated before any mechanism.

Concept: API1:2023 Broken Object Level Authorization (OWASP API Security Top 10, 2023 revision; still the current API list as of 2026-10). Authorization must be checked per object, not per session.

Concept: API7:2023 Server-Side Request Forgery. The server fetches attacker-chosen URLs.

Regression control: A request with a forged tenant claim returns zero rows; the CI fixture sweeps omit/foreign/empty/array tenant inputs.

Concept: Passkeys/WebAuthn as the phishing-resistant credential. Mechanism here; flows in 07.
Vulnerable pattern: Two-factor via SMS OTP as the only second factor, or an optional phishable TOTP that users routinely skip.
Why it fails: OTP codes are replayable, phishables, and SMS depends on the carrier; an attacker who can phish a login page can often relay the second factor.
Remediation: Prefer passkeys (FIDO2) for human primary authentication; require phishing-resistant MFA for production access and gate sensitive actions behind step-up authentication; keep recovery paths equally strong because account recovery is the usual bypass.
Regression control: Login-flow tests confirm phishing-resistant MFA for admin; recovery flows tested for bypass attempts and logged.
